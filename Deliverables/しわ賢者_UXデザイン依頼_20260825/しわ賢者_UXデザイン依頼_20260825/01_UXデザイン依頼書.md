## 最重要のデザイン制約

### Powaは変更しない

Powaは本作の既存キャラクター資産であり、今回のリデザイン対象ではありません。`references/powa_originals`に同梱した原画をそのまま使ってください。

- 描き直し、別キャラクター化、生成AIによる再解釈をしない。
- 顔、衣装、ポーズ、輪郭、色、質感を変更しない。
- 横方向・縦方向だけを伸ばす変形をしない。
- 等比率の拡大縮小、レイアウト上の移動は可能。
- 重要部分、とくに顔や手元をUIで隠さない。
- 既存アニメーション用のIdle、Attack、Damageも同じ見た目を維持する。

[[IMAGE:Powa_Idle.png|Powa原本。キャラクター自体は変更せず、そのまま使用する。|1.65]]

### 実装に合わせる

デザインは既存Unity uGUIへ実装可能な構成にしてください。大規模な3D化、別レンダリング方式への移行、独自シェーダー前提、過剰な常時アニメーションは対象外です。

### 画面を増やしすぎない

独立画面は次の4画面を維持します。

- Title
- StageSelect
- Main
- Result

データエラー、広告待機、保存通知、ロック状態は新しいSceneではなく、既存画面内のモーダル、インライン表示、トースト、disabledで解決してください。

## ゲーム概要

プレイヤーは右から流れてくる車を確認し、画面下部の3車種ボタン、または必要時の整備ボタンを押して仕分けます。放置ゲームではなく、短時間の判断と入力を繰り返すアクションゲームです。

ゲームモードは次の3つです。

1. おしごと：3章 x 5面、合計15面
2. デイリー：JST日付単位、60秒、3ミス
3. エンドレス：最高クリア済み面に応じた難易度、1ミス終了

特殊要素は故障車、覆面車、急送車、コンボ、Fever、Rushです。ショップ、コイン、ガチャ、ランキング、アカウント、課金画面は今回の対象ではありません。

## 今回のゴール

- 初見プレイヤーが、見る対象と押すボタンを理解できる。
- おしごと1から15まで迷わず進行できる。
- おしごと5クリア後にDailyとEndlessが解放されたことを理解できる。
- Pause、失敗、復活、広告失敗、Resultから必ず抜けられる。
- 保存やStageDatabaseの異常時に無言停止しない。
- 片手操作を前提に、主要入力を画面下半分へ保つ。
- 1080x1920、1170x2532、1440x3200でSafe Area内に収める。

## 現状の到達点

正常系では15面、Daily、Endless、Tutorial、Pause、Continue、Resultが実装されています。既存の回帰証跡では3画面比率 x 14状態が検証されています。ただし、次の公開前課題があります。

### P0

1. StageDatabase欠落・不正時に、復旧可能なブロッキング表示がない。
2. Main開始前に、選択面が存在・実装・解放済みかを再確認するUXがない。
3. 広告SDKのコールバックが返らない時、ContinueまたはResultが永久待機し得る。

### P1

1. StageSelectのSettings、How To、前へ、次へが未接続。
2. バックグラウンド復帰時の自動Pause案内がない。
3. Resultの広告待機理由が見えない。
4. 故障、覆面、急送をHow Toから再確認できない。
5. Daily保存データの自動再作成が無言で行われる。

## 画面別の主要依頼

### Title

おしごと、Daily、Endlessの優先順位を明確にし、未解放モードは押せないことと解放条件を同時に伝えてください。SettingsとHow Toは主操作より弱く、しかし発見可能な位置へ置きます。

[[IMAGE:Title_ModesLocked_Android_1080x1920.png|現行Title。Powaと世界観は維持し、モードの状態差を整理する。|2.75]]

### StageSelect

3章 x 5面、MISSION、BEST SCORE、星、解除条件を保ちます。スワイプに加えて前へ／次へを設け、SettingsとHow Toへ到達できるようにします。選択中とロック中を色だけに依存せず区別してください。

[[IMAGE:StageSelect_Chapter1_Android_1080x1920.png|現行StageSelect。カード情報を維持し、前後操作と補助導線を追加する。|2.75]]

### Main

プレイ中の優先順位は、目標進捗、ミス残数、車両、特殊状態、3車種ボタン、必要時の整備ボタンです。主要ボタンを下半分へ保ちます。Powaや背景演出が判断対象を妨げないようにしてください。

[[IMAGE:Main_Stage15Hud_Android_1080x1920.png|現行Main。情報量が最大のStage15を基準に整理する。|2.75]]

### Result

結果、SCORE、BEST、車種内訳、ミス、キャンペーンのみ星を表示します。次に押す主操作を1つだけ強くし、Retry、Next、StageSelect、Titleを状態に応じて整理します。広告待機中は、ボタンを無言で無効にしないでください。

[[IMAGE:Result_Clear_Android_1080x1920.png|現行Result。モード別に主操作と補助操作を整理する。|2.75]]

## Mainの情報設計

1. 上部：モード／ステージ名、目標進捗、ミス残数、Pause
2. 中央：車両表示、覆面／急送／故障状態、Fever／Rush
3. 下部：LightTruck、CompactCar、SportsCar、必要時の整備、判定フィードバック

上部は読む情報、中央は判断対象、下部は押す場所として役割を混ぜないでください。

## 必須状態セット

| 画面 | 必須状態 |
|---|---|
| Title | Daily/Endless locked、unlocked、初回How To |
| StageSelect | 章1/2/3、選択、ロック、最終面、前後端 |

| Continue | 通常、広告読込中、失敗、タイムアウト、Give Up |
| Result | Clear、Game Over、Daily、Endless、広告待機、広告失敗 |
| 共通 | StageDatabase異常、保存再作成、バックグラウンド復帰 |

## 受入条件

- Powaの形状、色、表情、衣装、ポーズが原本から変更されていない。
- 15面、Daily、Endlessの導線がすべて示されている。
- locked、disabled、loading、failureが色だけに依存しない。
- 広告が応答しなくても、最終的にResult操作へ到達できる。
- StageDatabase異常時に無言停止せず、RetryまたはTitleへ戻れる。
- Mainの主要操作が画面下半分にある。
- 3端末比率で文字切れ、重なり、Safe Area逸脱がない。
- 仕様外画面が追加されていない。

## デザイナーへ確認してほしい判断点

1. StageSelectの前後Buttonをカード左右と下部ドット周辺のどちらに置くか。
2. Mainでモード／ステージ名を常時表示しても判断領域を圧迫しないか。
3. 特殊車説明をHow To内の1セクションにするか、ページ切替にするか。
4. 広告待機を既存カード内のインライン状態にするか、半透明ブロッキング表示にするか。
5. データエラーを全Scene共通モーダルとして統一できるか。
